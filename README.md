# TRPG Archive（初期版）

GitHub Pages + Supabase で動く、個人用TRPGシナリオ管理アプリです。PCで選択したシナリオフォルダをスキャンして、分類・かな・タイトル・サムネイルを取り込みます。スマホからは同じURLにログインして一覧・検索・フィルター・詳細編集ができます。

## できること

- 6つの大分類（`00_公式シナリオ` ～ `05_企画`）を自動判別
- 直下のシナリオフォルダ名 `よみ一文字目＿シナリオタイトル` を分割
- シナリオフォルダ内の画像ファイルからサムネイル候補を1枚取得（8MB以下）
- 一覧、タイトル・作者検索、分類・人数・状態フィルター、ソート
- KP済・PL済・既読・お気に入り・R指定・人数・有償・作者名・URL・メモを管理
- CSV取り込み（既存スプレッドシートの移行用）・JSON書き出し
- フォルダを再スキャンして新規・変更・未検出を反映

## フォルダ構成

```text
Scenario/
├── 00_公式シナリオ/
│   ├── あ＿シナリオタイトル/
│   └── か＿シナリオタイトル/
├── 01_キャンペーン/
├── 02_シナリオ集/
├── 03_単品シナリオ/
├── 04_個人頒布/
└── 05_企画/
```

フォルダ名の区切りは全角アンダースコア `＿` と半角 `_` の両方に対応します。区切りの左側の先頭1文字を「かな」、区切りより右側をシナリオ名として扱います。

## セットアップ

### 1. Supabase

1. Supabaseで新しいプロジェクトを作成します。
2. 左メニューの **SQL Editor** を開きます。
3. `supabase/schema.sql` の内容を貼り付けて実行します。
4. **Project Settings → API** から Project URL と anon / publishable key を控えます。
5. Authentication の Email/Password を有効にします。
6. **Authentication → URL Configuration** の Site URL にGitHub PagesのURLを設定し、Redirect URLsにも同じURLを追加します。メール確認を有効にする場合は、確認メール内のリンクから登録を完了してください。

SQLはシナリオ情報テーブル、ユーザー別アクセス制御（RLS）、非公開サムネイルバケットを作成します。

### 2. アプリ設定

`config.js` を開き、以下を自分のSupabase情報に置き換えます。

```js
window.TRPG_ARCHIVE_CONFIG = {
  supabaseUrl: "https://自分のプロジェクトID.supabase.co",
  supabaseAnonKey: "自分のanonまたはpublishable key"
};
```

`config.js` はブラウザに公開されます。ここに **service_role key / secret key を絶対に書かないでください**。公開キーを使用し、データ保護はSQLで設定したRLSで行います。

### 3. GitHub Pages

1. GitHubで新しいリポジトリを作成します（Privateでも利用可能ですが、Pagesの利用条件はGitHubのプラン・リポジトリ設定を確認してください）。
2. このフォルダ内のファイルをリポジトリ直下にアップロードします。
3. リポジトリの **Settings → Pages** を開きます。
4. **Deploy from a branch** を選び、`main` ブランチの `/ (root)` を指定して保存します。
5. 発行された `https://ユーザー名.github.io/リポジトリ名/` をPC・スマホで開きます。

GitHub Pages自体は静的サイトの公開サービスです。シナリオデータはGitHubではなくSupabaseに保存されます。

### 4. 初回ログインとフォルダ登録

1. 公開URLをPC版ChromeまたはEdgeで開きます。
2. メールアドレスとパスワードでアカウントを新規登録し、必要ならメール確認を行います。
3. **フォルダを選択**を押し、6つの分類フォルダが入っている最上位フォルダ（例：`Scenario`）を選択します。
4. スキャンが終わると一覧が作成されます。
5. 各カードを開き、人数・R指定・有償・KP/PL・既読・作者・URL・メモを入力します。
6. スマホでも同じURLにログインすれば一覧を利用できます。

## 仕様・注意点

- フォルダ選択・再スキャンはPC版Chrome / Edgeを推奨します。GitHub PagesのHTTPS上で動作します。
- フォルダのアクセス権限はブラウザに保存されます。ブラウザの設定や権限状態によっては、再選択・再許可が必要です。
- スマホは同期済みデータの閲覧・編集用です。ローカルPCフォルダのスキャンはできません。
- 再スキャンはKP/PL・既読・作者名・URL・メモなどを上書きしません。フォルダ由来の分類・かな・タイトル・パスだけを更新します。
- フォルダが見つからなくなっても、データベースから削除せず「フォルダ未検出」として残します。
- フォルダ名を変更すると別のフォルダとして新規登録され、旧データは未検出になります。旧データの状態は自動移行しません（CSV取込で作成した未分類レコードはタイトルが一意に一致すれば紐付けます）。
- サムネイルはシナリオフォルダ直下の画像ファイルから1枚選び、Supabase Storageへコピーします。`サムネ`・`表紙`・`cover`・`thumbnail` を含む名前を優先します。サブフォルダ内の画像は初期版では検索しません。
- サムネイルはSupabaseの非公開ストレージに保存され、ログイン後に署名付きURLで表示します。
- PDFなどのシナリオ本文はアップロードしません。PC内の元フォルダに残します。
- データはSupabase上に保存されます。JSON書き出しを定期的に行ってバックアップしてください。
- CSV取り込みで既存レコードに一致する場合、空欄ではない項目を更新します。CSVの空欄で既存の作者名・URL・メモなどを消さない設計です。
- この初期版は自分のアカウントでの個人利用を想定しています。公開運用前に自分のSupabaseプロジェクトでログイン・RLS・画像表示を確認してください。

## 技術構成

- Frontend: HTML / CSS / JavaScript
- Hosting: GitHub Pages
- Database / Auth / Storage: Supabase
- Local folder read: File System Access API
